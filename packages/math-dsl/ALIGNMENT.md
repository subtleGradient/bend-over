# Math DSL alignment with mathlib and physlib

Survey for [W-BO-MD-1 and W-BO-MD-6](https://github.com/subtleGradient/bend-over/blob/main/packages/math-dsl/WISHES.md). This is a naming/structure note for a future **semantic** Bend IR, not an implemented API or a claim that captured equations have been proved. “Covered” means a corresponding mathematical construction exists in Lean; it does not mean mathlib has a generic equation-layout AST. Candidate names below are suggestions, not declarations.

| W-BO-MD-1 concept | Alignment / gap | Proposed IR convention and rationale |
| --- | --- | --- |
| Arithmetic | **Covered:** Lean's overloaded `+`, `-`, `*`, `/` and unary `-` use operations such as `HAdd.hAdd`, `HSub.hSub`, `HMul.hMul`, `HDiv.hDiv`, `Neg.neg` ([Lean core](https://leanprover-community.github.io/mathlib4_docs/Init/Prelude.html)). | Keep `add`, `sub`, `mul`, `div`, `neg` with explicit operands; preserve order (multiplication need not commute). |
| Fractions | **Covered semantically:** division `/` (`HDiv.hDiv`) and inverses `⁻¹` ([Lean core](https://leanprover-community.github.io/mathlib4_docs/Init/Prelude.html)). | Use `div` for a numerator/denominator; a stacked fraction is a renderer choice, not a different operation. |
| Roots | **Covered:** `Real.sqrt` and `Real.sqrt_eq_rpow` relate square roots to real powers; `Real.rpow` covers real exponents ([real powers](https://leanprover-community.github.io/mathlib4_docs/Mathlib/Analysis/SpecialFunctions/Pow/Real.html#Real.sqrt_eq_rpow)). | Use `sqrt` for square roots and `pow`/`rpow` for powers; a general nth-root spelling, if needed, should follow the chosen domain's library operation rather than assume all roots share one semantics. |
| Superscripts (powers) | **Covered:** `^` is power; `Real.rpow` distinguishes real exponents from natural/integer powers ([real powers](https://leanprover-community.github.io/mathlib4_docs/Mathlib/Analysis/SpecialFunctions/Pow/Real.html#Real.rpow)). | Use `pow` (or `rpow` when the exponent's domain requires it); a superscript that is a label is **not** exponentiation—see indexed tensors below. |
| Subscripts (indexing) | **Covered semantically:** function application `M i j` accesses a `Matrix m n α`; its indices are typed, not text ([Matrix definitions](https://leanprover-community.github.io/mathlib4_docs/Mathlib/LinearAlgebra/Matrix/Defs.html#Matrix)). | Use application / `eval` with an explicit index; subscripts used merely to distinguish variable names are part of the symbol identity, not an operation. |
| Sums with binders | **Covered:** `Finset.sum s (fun i => f i)` and notation `∑ i ∈ s, f i` ([finite big operators](https://leanprover-community.github.io/mathlib4_docs/Mathlib/Algebra/BigOperators/Group/Finset/Defs.html#Finset.sum)). | Follow `Finset.sum`: retain a domain and an actual bound variable in the body; renaming it must not change meaning. |
| Products with binders | **Covered:** `Finset.prod s (fun i => f i)` and `∏ i ∈ s, f i` ([finite big operators](https://leanprover-community.github.io/mathlib4_docs/Mathlib/Algebra/BigOperators/Group/Finset/Defs.html#Finset.prod)). | Follow `Finset.prod` and the same binding structure as `Finset.sum`. |
| Integrals with binders | **Covered:** `MeasureTheory.integral μ (fun x => f x)`, notation `∫ x, f x ∂μ`; interval notation has bounds ([Bochner integral](https://leanprover-community.github.io/mathlib4_docs/Mathlib/MeasureTheory/Integral/Bochner/Basic.html#MeasureTheory.integral), [interval integral](https://leanprover-community.github.io/mathlib4_docs/Mathlib/MeasureTheory/Integral/IntervalIntegral/Basic.html)). | Use `integral` with bound variable, domain/limits when applicable, integrand and measure; `dx` is a rendering of the binder/measure, not a free string. Keep interval and measure-integral semantics distinguishable. |
| Total derivatives | **Covered:** `deriv f x` for one-dimensional functions and `HasDerivAt f f' x` for statements about derivatives ([derivative definitions](https://leanprover-community.github.io/mathlib4_docs/Mathlib/Analysis/Calculus/Deriv/Basic.html#deriv)). | Use `deriv` for the value and `HasDerivAt` only for a proposition. Bind the function's variable rather than store a printed `d/dx`. |
| Partial derivatives | **Covered via structure:** `fderiv 𝕜 f x` is a Fréchet derivative (a linear map); applying it to a basis direction gives a coordinate partial derivative ([Fréchet derivative](https://leanprover-community.github.io/mathlib4_docs/Mathlib/Analysis/Calculus/FDeriv/Defs.html#fderiv)). Physlib uses `Space.deriv μ f` and `∂[μ] f` with `Fin d` direction ([Physlib spatial derivatives](https://github.com/leanprover-community/physlib/blob/master/Physlib/SpaceAndTime/Space/Derivatives/Basic.lean)). | Prefer `fderiv` + direction, or `Space.deriv` in that domain; distinguish a coordinate derivative from the whole Fréchet map. The chosen coordinate is bound in the function body. |
| Limits | **Covered:** `Filter.Tendsto f l (nhds y)` states convergence; `Filter.limUnder l f` chooses a limit where appropriate; `nhds`, `nhdsWithin` and `Filter.atTop` express approaches ([topological filters](https://leanprover-community.github.io/mathlib4_docs/Mathlib/Topology/Defs/Filter.html#Filter.limUnder), [Tendsto](https://leanprover-community.github.io/mathlib4_docs/Mathlib/Order/Filter/Defs.html#Filter.Tendsto)). | Use `Tendsto` for a claim and `limUnder` for a limit term, with an approach filter and a bound input variable; do not encode `x → a` as text. |
| Matrices | **Covered:** `Matrix m n α` is `m → n → α`, constructed using `Matrix.of`, with typed row/column indices; `Fin m`/`Fin n` give finite dimensions ([Matrix definitions](https://leanprover-community.github.io/mathlib4_docs/Mathlib/LinearAlgebra/Matrix/Defs.html#Matrix)). | Follow `Matrix` / `Matrix.of`, retaining row/column dimensions and entry ordering rather than only a rendered grid. |
| Indexed tensors | **Covered in physlib:** `TensorSpecies` records index colors/duals; `{T | μ ν}ᵀ` elaborates to a tensor tree, repeated indices contract via `Tensor.contrT`, and `τ(μ)` changes duality ([species](https://github.com/leanprover-community/physlib/blob/master/Physlib/Relativity/Tensors/TensorSpecies/Basic.lean), [elaborator](https://github.com/leanprover-community/physlib/blob/master/Physlib/Relativity/Tensors/Elab.lean)). | Align with `TensorSpecies.Tensor`, `Tensor.prodT`, `Tensor.contrT`, `Tensor.evalT` and typed index slots. Physlib does not infer raised/lowered slots from typography alone: color/dual information belongs to the tensor, and repeated dummy names are alpha-renamable. |
| Greek symbols | **Covered as identifiers:** Lean/physlib use Unicode names such as `μ`, `ν` for indices and `α`, `β` for parameters ([physlib tensor elaborator](https://github.com/leanprover-community/physlib/blob/master/Physlib/Relativity/Tensors/Elab.lean)). | Treat Greek letters as symbol names, not distinct operators; retain exact identifier identity for rendering. |
| Common symbols | **Covered where meaningful:** Lean provides `ℕ`, `ℤ`, `ℝ`, `ℂ`, `π` (`Real.pi`), and mathematical operator notation ([Lean core](https://leanprover-community.github.io/mathlib4_docs/Init/Prelude.html), [real powers using `Real.pi`](https://leanprover-community.github.io/mathlib4_docs/Mathlib/Analysis/SpecialFunctions/Pow/Real.html)). | Use established names for known constants/types/operators; other letters are typed identifiers. A glyph alone cannot decide whether `i` is an index, imaginary unit or a free variable. |
| Text annotations | **Gap:** a paper's explanatory prose within an equation has no general mathlib/physlib mathematical operator; Lean documentation comments are outside terms ([physlib documented definitions](https://github.com/leanprover-community/physlib/blob/master/Physlib/SpaceAndTime/Space/Derivatives/Basic.lean)). | Propose `annotation(text, term)` as separate metadata on a semantic term, not an uninterpreted math subexpression; renderers may display it while proof translation ignores the prose. |

The only proposed new form here is annotation metadata. Script position, stacked division, radical shape and `dx` spelling are rendering concerns; matching the library's *mathematical* structure takes precedence over matching a glyph. Bound names in sums, products, integrals, derivatives and limits must be alpha-renamable; tensor dummy indices likewise must not change meaning when renamed. Any future new semantic node without a corresponding library convention should be documented here with its rationale before implementation and considered for upstream discussion.
